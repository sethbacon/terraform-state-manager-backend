# THE INTEGRATION PACKAGE FLOOR.
#
# Every package listed here MUST contribute at least one passing, top-level,
# integration-tagged test to the Postgres job's transcript. The list is checked
# BOTH ways by assert_integration_tests_ran.sh: a package here that the tree no
# longer supplies is a failure, and a package the tree supplies that is not here
# is also a failure.
#
# Why a committed list at all, when the script derives the packages from the
# tree? Because every derivation there reads the TREE, and a tree that no longer
# contains a suite has nothing to derive. A derived set shrinks silently; a set
# checked against a committed one cannot. Deleting the tagged file, or renaming
# it and its tests, removes it from all three derivations at once, and this list
# is the only thing left that remembers the package existed.
#
# It is NOT the file-granular floor, and it cannot be made into one. This list is
# PACKAGE-granular by construction, so a package that keeps even one tagged file
# still satisfies it. The floor that fails when ONE file leaves the build is the
# toolchain floor in assert_integration_tests_ran.sh, which asks `go list` which
# files each build actually compiles. The two cover different losses: the
# compiler can only speak about files that are still there, and this list only
# speaks about packages. Neither replaces the other.
#
# Removing an entry is therefore a deliberate, reviewable act that says in the
# diff: "this package no longer proves anything against a real database."
# Adding a suite means adding its package here in the same commit.
#
# Paths are module-relative, one per line. `#` comments and blank lines ignored.
